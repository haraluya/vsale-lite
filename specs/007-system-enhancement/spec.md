# Feature Specification: 系統擴充功能集

**Feature Branch**: `007-system-enhancement`
**Created**: 2026-01-03
**Status**: Draft
**Input**: User description: "系統擴充功能：價格機制優化、訂單留言系統、客戶管理擴充、系列頁圖片切換、廣告輪播系統"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 訂單雙向溝通系統 (Priority: P0)

批發商與客戶需要在訂單處理過程中進行即時溝通，解決訂單相關問題（如缺貨替代、地址確認、特殊需求等）。目前系統僅支援客戶下單時留下單次備註，無法進行後續對話。

**Why this priority**: 訂單溝通是批發業務的核心需求，直接影響訂單處理效率與客戶滿意度。目前客戶與管理員需透過 LINE/電話溝通，資訊分散且難以追蹤。

**Independent Test**: 可透過建立測試訂單，由客戶端與管理端分別新增留言，驗證留言顯示、時間軸排序、角色區分是否正確。

**Acceptance Scenarios**:

1. **Given** 客戶已登入且有待處理訂單，**When** 客戶在訂單詳情頁輸入留言並提交，**Then** 留言顯示在時間軸（左側灰色氣泡），管理員可在後台看到
2. **Given** 管理員已登入並查看訂單詳情，**When** 管理員回覆客戶留言，**Then** 留言顯示在時間軸（右側藍色氣泡），客戶可在前台看到
3. **Given** 訂單存在客戶下單時的備註，**When** 查看訂單詳情，**Then** 原始備註與留言分開顯示，留言依時間排序
4. **Given** 客戶嘗試在他人訂單留言，**When** 提交留言，**Then** 系統拒絕並回傳 403 權限錯誤
5. **Given** 留言超過 500 字，**When** 提交留言，**Then** 系統顯示錯誤提示並禁止提交

### User Story 2 - 客戶資訊完整化管理 (Priority: P0)

管理員需要記錄客戶的常用地址與內部備註（如客戶偏好、特殊要求、信用評級等），以便在處理訂單時快速參考，提升服務品質。目前系統僅有基本客戶資訊，缺乏業務所需的輔助資訊。

**Why this priority**: 完整的客戶資訊能顯著提升訂單處理效率，減少重複詢問，並支援個性化服務。這是批發業務的標準需求。

**Independent Test**: 可透過編輯客戶資料，新增地址與備註，然後在訂單詳情頁驗證資訊顯示是否正確，並確認客戶端無法看到管理員備註。

**Acceptance Scenarios**:

1. **Given** 管理員在客戶編輯頁面，**When** 填寫常用地址與管理員備註並儲存，**Then** 資料成功儲存且顯示在客戶列表摘要欄位
2. **Given** 管理員查看訂單詳情，**When** 訂單關聯的客戶有地址與備註，**Then** 訂單頁顯示客戶地址與備註，並提供快速跳轉編輯按鈕
3. **Given** 客戶登入系統，**When** 客戶查看自己的訂單或個人資料，**Then** 客戶無法看到管理員備註欄位（RLS 權限保護）
4. **Given** 客戶列表顯示地址與備註，**When** 文字超過 30 字，**Then** 自動截斷並顯示「...」

### User Story 3 - 系列頁商品圖片即時預覽 (Priority: P1)

客戶瀏覽系列頁面時，希望快速查看每個商品的實際圖片，而不需跳轉到商品詳情頁。目前系列頁僅顯示系列代表圖，客戶需逐一點擊商品才能看到個別圖片，操作繁瑣。

**Why this priority**: 提升前台瀏覽體驗，減少頁面跳轉次數，讓客戶更快速地找到目標商品。特別適合視覺導向的商品（如服飾、配件）。

**Independent Test**: 可在系列頁點擊有圖片的商品卡片，驗證大圖是否切換為商品圖片，並測試點擊空白處或 X 按鈕是否能恢復系列圖片。

**Acceptance Scenarios**:

1. **Given** 系列頁載入完成，**When** 頁面顯示，**Then** 頂部大圖顯示系列代表圖片
2. **Given** 商品卡片有設定圖片，**When** 客戶點擊商品卡片，**Then** 大圖切換為商品圖片，並顯示關閉按鈕
3. **Given** 大圖顯示商品圖片，**When** 客戶點擊空白處或關閉按鈕，**Then** 大圖恢復為系列圖片
4. **Given** 商品卡片無設定圖片，**When** 滑鼠移至卡片上，**Then** 卡片呈現禁用狀態（半透明），點擊無反應
5. **Given** 圖片切換時，**When** 執行切換動作，**Then** 圖片以淡入淡出動畫呈現（300ms 過渡）

### User Story 4 - 廣告輪播系統 (Priority: P1)

管理員需要在前台首頁展示促銷活動、新品上架、重要公告等資訊，吸引客戶注意並引導點擊。目前首頁僅有商品系列列表，缺乏行銷推廣入口。

**Why this priority**: 廣告輪播是電商系統的標準功能，能有效提升促銷活動曝光率與轉換率，是業務拓展的重要工具。

**Independent Test**: 可在後台新增測試廣告並設定連結，然後在前台首頁驗證輪播顯示、點擊跳轉、左右切換是否正常運作。

**Acceptance Scenarios**:

1. **Given** 管理員在廣告管理頁面，**When** 新增廣告並上傳圖片、設定標題與連結，**Then** 廣告成功建立並顯示在列表
2. **Given** 存在多則啟用的廣告，**When** 客戶開啟前台首頁，**Then** 首頁頂部顯示輪播元件，每 5 秒自動切換
3. **Given** 輪播顯示某則廣告，**When** 客戶點擊左右箭頭，**Then** 輪播切換至上一則或下一則廣告
4. **Given** 廣告有設定連結，**When** 客戶點擊廣告圖片，**Then** 頁面跳轉至設定的連結
5. **Given** 管理員停用某則廣告，**When** 客戶重新載入首頁，**Then** 該廣告不再顯示在輪播中
6. **Given** 廣告超過 5 則，**When** 前台載入，**Then** 僅顯示排序最前的 5 則廣告

### User Story 5 - 價格管理優化（按商品設定） (Priority: P2)

管理員需要針對單一商品設定所有會員等級的價格，而不需先選擇系列。目前價格管理頁僅支援「選擇系列」模式，當管理員需要調整特定商品價格時，需先記住該商品屬於哪個系列，操作不直覺。

**Why this priority**: 提升管理端操作效率，特別適合需要針對熱門商品或促銷商品快速調價的場景。雖非核心功能，但能顯著改善使用體驗。

**Independent Test**: 可在價格管理頁切換至「選擇商品」模式，選擇單一商品，驗證所有等級的價格是否正確顯示，並測試價格儲存功能。

**Acceptance Scenarios**:

1. **Given** 管理員在價格管理頁面，**When** 點擊「選擇商品」標籤，**Then** 顯示商品下拉選單與價格設定表格
2. **Given** 管理員選擇某個商品，**When** 載入完成，**Then** 表格顯示該商品 × 所有會員等級的價格矩陣
3. **Given** 零售等級的價格欄位，**When** 顯示在表格中，**Then** 欄位為唯讀狀態（顯示但禁用輸入）
4. **Given** 管理員修改非零售等級價格並儲存，**When** 提交表單，**Then** 價格成功更新且頁面顯示成功提示
5. **Given** 管理員需修改零售價格，**When** 查看提示訊息，**Then** 系統提示「零售價格請至商品編輯頁修改」

---

### Edge Cases

- **訂單留言系統**:
  - 當訂單已取消時，客戶與管理員是否仍可留言？（建議：允許留言，用於售後溝通）
  - 當留言包含特殊字元或 HTML 標籤時，系統如何處理？（建議：自動轉義，防止 XSS 攻擊）
  - 當同時有多人在同一訂單留言時，時間軸排序是否正確？（建議：依伺服器時間戳排序）

- **客戶管理擴充**:
  - 當地址或備註欄位為空時，客戶列表與訂單詳情頁如何顯示？（建議：顯示「未設定」或空白）
  - 當管理員備註包含敏感資訊時，如何確保客戶端無法透過 API 查詢？（建議：RLS 策略嚴格控制）

- **系列頁圖片切換**:
  - 當商品圖片載入失敗時，大圖如何顯示？（建議：顯示預設佔位圖）
  - 當系列包含大量商品（如 100+）時，圖片切換效能是否受影響？（建議：使用 Next.js Image 元件優化）

- **廣告輪播系統**:
  - 當所有廣告都被停用時，首頁如何顯示？（建議：隱藏輪播元件）
  - 當廣告圖片尺寸不一致時，輪播如何處理？（建議：使用 object-cover 裁切）
  - 當圖片上傳失敗時，管理員如何得知？（建議：顯示錯誤訊息並禁止儲存）

- **價格管理優化**:
  - 當商品未設定任何等級價格時，表格如何顯示？（建議：顯示空白欄位，允許管理員直接填寫）
  - 當管理員在「選擇商品」模式與「選擇系列」模式間切換時，已填寫但未儲存的資料是否保留？（建議：提示使用者先儲存）

## Requirements *(mandatory)*

### Functional Requirements

**訂單留言系統**:

- **FR-001**: 系統必須允許客戶在自己的訂單詳情頁新增留言（最多 500 字）
- **FR-002**: 系統必須允許管理員在任何訂單詳情頁新增留言（最多 500 字）
- **FR-003**: 系統必須將留言與原始訂單備註分開顯示，原始備註標題為「客戶備註」，留言區標題為「操作歷史與留言」
- **FR-004**: 系統必須以時間軸方式顯示留言，客戶留言靠左（灰色背景），管理員留言靠右（藍色背景）
- **FR-005**: 系統必須在每則留言顯示發言人姓名、角色標籤（客戶/管理員）、發言時間
- **FR-006**: 系統必須阻止客戶在他人訂單留言，並回傳 403 權限錯誤
- **FR-007**: 系統必須在留言輸入框提供即時字數統計（X / 500）

**客戶管理擴充**:

- **FR-008**: 系統必須允許管理員在客戶編輯頁新增/修改「常用地址」欄位（文字區域，3 行高度）
- **FR-009**: 系統必須允許管理員在客戶編輯頁新增/修改「管理員備註」欄位（文字區域，3 行高度）
- **FR-010**: 系統必須在客戶列表顯示地址與備註摘要（最多 30 字，超過顯示「...」）
- **FR-011**: 系統必須在訂單詳情頁的客戶資訊區塊顯示客戶地址與管理員備註
- **FR-012**: 系統必須在訂單詳情頁提供「編輯客戶資料」快速跳轉按鈕
- **FR-013**: 系統必須確保客戶端無法查詢或顯示管理員備註欄位（RLS 權限保護）

**系列頁圖片切換**:

- **FR-014**: 系統必須在系列詳情頁頂部顯示大圖區域（預設顯示系列圖片）
- **FR-015**: 系統必須允許客戶點擊有圖片的商品卡片，大圖切換為商品圖片
- **FR-016**: 系統必須在大圖顯示商品圖片時，提供關閉按鈕（X 圖示）
- **FR-017**: 系統必須允許客戶點擊空白處或關閉按鈕，大圖恢復為系列圖片
- **FR-018**: 系統必須將無圖片的商品卡片設為禁用狀態（半透明，無點擊效果）
- **FR-019**: 系統必須在圖片切換時使用淡入淡出動畫（300ms 過渡效果）

**廣告輪播系統**:

- **FR-020**: 系統必須在前台首頁頂部（系列列表上方）顯示廣告輪播元件
- **FR-021**: 系統必須僅顯示已啟用的廣告，依排序欄位排序，最多顯示 5 則
- **FR-022**: 系統必須提供左右箭頭切換廣告，並顯示指示器（圓點）標示當前位置
- **FR-023**: 系統必須支援自動播放功能（每 5 秒自動切換至下一則）
- **FR-024**: 系統必須允許客戶點擊廣告圖片，若有設定連結則跳轉至該連結
- **FR-025**: 系統必須提供後台廣告管理頁面，支援新增/編輯/刪除/啟用/停用廣告
- **FR-026**: 系統必須支援廣告圖片上傳至 Supabase Storage（格式：JPG/PNG/WebP，最大 5MB，儲存路徑：`announcements/{announcement_id}/main.{ext}`）
- **FR-027**: 系統必須允許管理員設定廣告標題、連結（選填）、排序數字

**價格管理優化**:

- **FR-028**: 系統必須在價格管理頁面提供標籤切換（「選擇系列」與「選擇商品」）
- **FR-029**: 系統必須在「選擇商品」模式提供商品下拉選單（依系列分組，系列內依商品編號排序）
- **FR-030**: 系統必須在選擇商品後，顯示該商品 × 所有會員等級的價格矩陣表格
- **FR-031**: 系統必須將零售等級價格欄位設為唯讀（顯示但禁用輸入），並提示「請至商品編輯頁修改」
- **FR-032**: 系統必須允許管理員修改非零售等級價格並批次儲存

### Key Entities

- **OrderTimeline（訂單操作歷史）**: 記錄訂單的所有操作事件，包含留言。擴充 `action_type` 支援 `'comment'`，使用 `actor_role` 區分留言來源。
- **Profile（客戶資料）**: 擴充欄位包含 `address`（常用地址）與 `admin_notes`（管理員備註，取代原 `notes`）。
- **Announcement（廣告）**: 新增實體，包含標題、圖片 URL、連結 URL（選填）、排序、啟用狀態、建立/更新時間。
- **TierPrice（等級價格）**: 既有實體，價格管理優化功能需查詢與更新此表。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 客戶與管理員能在 3 秒內完成訂單留言提交，留言即時顯示在時間軸
- **SC-002**: 管理員能在客戶編輯頁 2 分鐘內完成地址與備註填寫並儲存
- **SC-003**: 客戶在系列頁點擊商品卡片後，商品圖片在 1 秒內完成切換並顯示
- **SC-004**: 前台首頁廣告輪播在頁面載入 2 秒內完成渲染，自動播放流暢無卡頓
- **SC-005**: 管理員在「選擇商品」模式下，能在 1 分鐘內完成單一商品的價格設定
- **SC-006**: 系統能確保 100% 的管理員備註無法被客戶端查詢或顯示（RLS 權限測試通過）
- **SC-007**: 訂單留言功能上線後，客戶與管理員透過系統內溝通的比例達 80% 以上（減少 LINE/電話溝通）
- **SC-008**: 廣告輪播點擊率（CTR）達 5% 以上（表示廣告能有效吸引客戶注意）
- **SC-009**: 系統能在同一訂單同時有 10 位使用者留言時，正確顯示所有留言且無時間軸錯亂
- **SC-010**: 管理員能在 30 秒內完成廣告的新增/編輯/刪除操作，並在前台即時生效

### Assumptions

- 客戶已熟悉訂單詳情頁的基本操作，知道如何查看訂單狀態
- 管理員已具備基本的後台操作能力，知道如何導航至各管理頁面
- 系統已完成訂單管理（004-cart-and-orders）功能，具備完整的訂單流程
- Supabase Storage 已正確設定，支援圖片上傳與公開讀取
- 所有新增功能均遵循 Neo-Brutalism 設計風格，與現有系統視覺一致
- 廣告圖片由管理員自行準備，系統不提供圖片編輯或裁切功能
- 價格管理優化僅針對「選擇商品」模式，不影響現有「選擇系列」模式的功能
