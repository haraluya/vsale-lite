# 功能規格：效能優化專案 - 智能快取策略與使用者體驗提升

**功能編號**：018
**功能名稱**：performance-optimization
**建立日期**：2026-01-17
**狀態**：Draft
**優先級**：P0（高優先級）

---

## 1. 概述

### 1.1 功能簡述

優化 Vsale-lite B2B 批發訂貨系統的效能，透過智能快取策略提升頁面載入速度，同時確保後台管理介面的資料即時性與正確性。解決目前系統中的效能瓶頸與使用者體驗問題。

### 1.2 業務價值

- **客戶體驗提升**：前台商品瀏覽速度提升 50% 以上，減少客戶等待時間
- **管理效率**：解決後台資料更新後需手動刷新的問題，提升管理員操作效率
- **系統穩定性**：降低伺服器負荷 40-50%，提升系統承載能力
- **成本節省**：減少不必要的資料庫查詢，降低 Vercel 和 Supabase 使用成本

### 1.3 目標使用者

- **前台客戶**：需要快速瀏覽商品、查看價格、下單的批發商
- **後台管理員**：需要即時管理商品、價格、訂單的系統管理人員

## 2. 使用者場景與測試

#### 場景 A：快速瀏覽商品目錄

**角色**：已登入的批發客戶
**目標**：快速瀏覽商品並查看價格

**流程**：
1. 客戶開啟商品列表頁面（/store/products）

4. 系統在 1 秒內顯示商品詳情（使用快取）
5. 客戶看到符合其會員等級的價格

**預期結果**：
- 頁面載入時間明顯縮短（比當前快 50% 以上）
- 價格顯示正確（符合客戶等級）
- 無白屏或長時間等待

- 購物車中的價格永遠是最新的

## 3. 功能需求

### 3.1 前台快取策略（FR-001）

**需求描述**：
前台商品相關頁面實作 ISR（增量靜態重新生成）快取策略，提升載入速度，同時保持合理的資料新鮮度。

**詳細規則**：
- 商品列表頁（/store/products）：快取 5 分鐘（revalidate: 300）
- 商品詳情頁（/store/[id]）：快取 10 分鐘（revalidate: 600）
- 系列頁面（/store/series/[id]）：快取 5 分鐘（revalidate: 300）
- 首頁（/store/home）：快取 5 分鐘（revalidate: 300）
- 購物車頁（/store/cart）：**不快取**（force-dynamic）
- 訂單頁（/store/orders）：**不快取**（force-dynamic）

**驗收標準**：
- 商品列表頁載入時間 < 1.5 秒（當前約 3-4 秒）
- 商品詳情頁載入時間 < 1 秒（當前約 2-3 秒）
- 購物車頁顯示即時價格（無延遲）

### 3.2 後台完全動態渲染（FR-002）

**需求描述**：
後台所有頁面保持動態渲染（force-dynamic），確保管理員看到的資料永遠是最新的。

**詳細規則**：
- 所有 `/admin/*` 路由的 layout.tsx 設定 `export const dynamic = 'force-dynamic'`
- 所有後台 page.tsx 設定 `export const dynamic = 'force-dynamic'`
- 價格管理頁面（/admin/tier-prices）必須即時反映資料變更
- 訂單管理頁面（/admin/orders）必須即時反映訂單狀態

**驗收標準**：
- 價格更新後，管理員立即在同一頁面看到新價格（無空白頁）
- 訂單狀態更新後，列表立即刷新
- 多個管理員同時操作時，看到的資料一致

**解決的問題**：
- **修復價格管理頁面更新後空白需刷新的 Bug**

### 3.3 快取失效機制（FR-003）

**需求描述**：
當資料變更時，自動失效相關的快取，確保前台使用者在合理時間內看到最新資料。

**快取標籤系統**：
- `products`：商品資料變更時失效
- `series`：系列資料變更時失效
- `categories`：分類資料變更時失效
- `tier-prices`：價格資料變更時失效
- `orders`：訂單資料變更時失效

**觸發時機**：
- 商品新增/更新/刪除 → `revalidateTag('products')` + `revalidatePath('/store')`
- 價格更新 → `revalidateTag('tier-prices')` + `revalidateTag('products')`
- 系列更新 → `revalidateTag('series')` + `revalidatePath('/store/series')`
- 訂單狀態變更 → `revalidateTag('orders')` + `revalidatePath('/admin/orders')`

**驗收標準**：
- 管理員更新價格後，前台客戶在 5 分鐘內看到新價格（最多延遲 = revalidate 時間）
- 管理員新增商品後，前台在 5 分鐘內顯示新商品
- Server Actions 執行完成後立即觸發快取失效

### 3.4 載入狀態 UI（FR-004）

**需求描述**：
所有需要動態載入的頁面都提供 Neo-Brutalism 風格的骨架屏（Skeleton Loading），提升使用者體驗。

**需要新增 loading.tsx 的路由**：
- `/store/series/[id]/loading.tsx` - 系列詳情頁
- `/store/orders/loading.tsx` - 客戶訂單列表
- `/admin/orders/loading.tsx` - 管理員訂單列表
- `/admin/tier-prices/loading.tsx` - 價格管理頁面
- `/admin/products/loading.tsx` - 商品管理頁面

**設計規範**：
- 使用 `border-2 border-black` 邊框
- 使用 `animate-pulse` 動畫效果
- 背景色使用 `bg-gray-100` 或 `bg-gray-200`
- 保持與實際內容相似的佈局結構

**驗收標準**：
- 頁面切換時立即顯示骨架屏（無白屏）
- 載入狀態視覺上符合 Neo-Brutalism 風格
- 骨架屏佈局與實際內容一致（避免佈局位移）

### 3.5 查詢並行化優化（FR-005）

**需求描述**：
將序列執行的獨立查詢改為並行執行，減少 waterfall 請求，提升頁面載入速度。

**優化位置**：

**A. Dashboard 查詢（lib/actions/dashboard.ts）**：
- 當前：9 個序列查詢
- 優化後：改為 Promise.all 並行執行，或使用 RPC 函數聚合

**B. 商品頁面查詢（app/(shop)/store/products/page.tsx）**：
```typescript
// 當前（序列）
const seriesResult = await getActiveSeries()
const categoriesResult = await getActiveCategories()
const tagsResult = await getAvailableTags()

// 優化後（並行）
const [seriesResult, categoriesResult, tagsResult] = await Promise.all([
  getActiveSeries(),
  getActiveCategories(),
  getAvailableTags(),
])
```

**C. 其他頁面的獨立查詢**：
- 系列詳情頁
- 管理員 Dashboard

**驗收標準**：
- Dashboard 載入時間減少 50% 以上
- 商品頁面載入時間減少 60% 以上（600ms → 200ms）
- 無資料不一致問題（確保查詢邏輯正確）

## 5. 關鍵實體

### 5.1 快取配置實體

**實體名稱**：CacheConfig
**說明**：頁面快取配置規則

**屬性**：
- `route`：路由路徑（如 /store/products）
- `strategy`：快取策略（ISR / force-dynamic）
- `revalidate`：重新驗證時間（秒，null 表示不快取）
- `tags`：快取標籤陣列（用於失效控制）

**範例**：
```typescript
{
  route: '/store/products',
  strategy: 'ISR',
  revalidate: 300,
  tags: ['products', 'series', 'categories']
}
```

### 5.2 快取失效事件

**實體名稱**：CacheInvalidationEvent
**說明**：觸發快取失效的資料變更事件

**屬性**：
- `action`：操作類型（create / update / delete）
- `entity`：實體類型（product / tier-price / order 等）
- `tags`：需要失效的快取標籤
- `paths`：需要重新驗證的路徑

**範例**：
```typescript
{
  action: 'update',
  entity: 'tier-price',
  tags: ['tier-prices', 'products'],
  paths: ['/store', '/store/[id]']
}
```

## 9. 風險與緩解

### 9.1 快取導致價格錯誤風險

**風險描述**：
客戶在快取期間看到舊價格，下單後發現價格已變動。

**緩解措施**：
- 購物車頁面和結帳流程**不使用快取**（force-dynamic）
- 訂單建立時再次查詢最新價格進行驗證
- 如果價格變動，顯示提示並要求客戶確認新價格

**影響等級**：低（已有緩解機制）

### 9.2 快取失效延遲風險

**風險描述**：
管理員更新價格後，前台客戶在 5 分鐘內仍看到舊價格。

**緩解措施**：
- 設定合理的 revalidate 時間（5 分鐘）
- 管理員更新後，系統顯示提示：「前台將在 5 分鐘內更新」
- 如需立即生效，管理員可手動觸發「清除快取」功能（可選）

**影響等級**：低（業務可接受）

### 9.3 後台頁面效能風險

**風險描述**：
後台所有頁面都不快取，可能導致載入速度較慢。

**緩解措施**：
- 實作查詢並行化（減少查詢時間 50%+）
- 後台頁面新增 Loading UI（改善感知效能）
- 管理員數量有限（< 10 人），伺服器負荷可控

**影響等級**：低（查詢優化已緩解）

### 9.4 空白頁面問題未解決風險

**風險描述**：
優化後，價格管理頁面的空白問題仍然存在。

**緩解措施**：
- 詳細調查當前空白問題的根因（可能是狀態管理或快取問題）
- 確保 Server Actions 執行後正確觸發 revalidatePath
- 測試驗證：更新後立即檢查頁面是否顯示正常

**影響等級**：中（需重點測試）
