# 010-media-library: Supabase Storage 圖片管理系統

> **狀態**: 📋 規劃完成，待未來實作
> **優先級**: P2
> **預估工時**: 10-13 天
> **建立日期**: 2026-01-06

---

## 🎯 功能概述

建立類似 WordPress 的媒體庫管理系統，解決當前圖片管理的痛點：

1. **DB 重置後圖片失聯問題**
2. **無統一圖片管理介面**
3. **無法識別與清理孤兒檔案**
4. **缺乏批次上傳功能**
5. **Excel 備份無法含圖片**

## 🚀 實作階段（預計）

### Phase 1: 基礎媒體庫（4-5 天）
- 建立 `media_library` 資料表
- 修改現有上傳邏輯同步寫入
- 基礎列表頁
- 孤兒檔案掃描

### Phase 2: 圖片選擇器（2-3 天）
- MediaPicker 元件
- 整合到商品/系列表單
- 「從媒體庫選擇」功能

### Phase 3: 批次上傳（3-4 天）
- 拖拽多檔案上傳
- 圖片詳情編輯
- 網格/列表視圖

### Phase 4: ZIP 備份（4-5 天）- 可選
- 圖片打包匯出
- ZIP 匯入功能
- ID 對應處理

## 🔗 相關問題

### 當前問題

1. **DB 重置時圖片會怎樣？**
   - 答：圖片失去連結但仍存在 Storage 中

2. **能否建立圖片管理平台？**
   - 答：可以，且建議實作（類似 WordPress 媒體庫）

3. **重新上傳商品能選舊圖嗎？**
   - 答：目前不行，需實作 MediaPicker 元件

4. **批次上傳難度高嗎？**
   - 答：中等，約 10-13 天完整開發

5. **Excel 能備份圖片嗎？**
   - 答：可以（ZIP 打包方式）

6. **整體實作難度？**
   - 答：中等（分階段實作較容易）
