### 2.2 架構設計

**雙入口認證系統**
- 客戶：手機號碼登入 → `/store`（行動優先）
- 管理員：Email 登入 → `/admin/dashboard`（桌面優先）
- Middleware 自動路由保護 + 角色 Cookie 快取（5 分鐘 TTL）

**App Router 結構**
```
app/
├── (auth)/          # 認證路由組
├── (admin)/admin/   # 管理後台（18+ 頁面）
├── (shop)/store/    # 前台商店（13+ 頁面）
├── api/             # API 端點（認證、備份、Cron）
└── offline/         # 離線回退頁面
```

**Server Actions 模式** — 27 個檔案，15,415 行程式碼
- 統一的 `ActionResult<T>` 返回型別
- `checkAuth()` 權限驗證（React `cache()` request-scoped 快取）
- Zod Schema 輸入驗證
- `revalidatePath()` 快取失效

**資料庫** — 32 個 Migration 檔案
- 完整的 RLS 策略（每張表都有）
- 資料庫函式：運費計算、訂單編號生成（防競態）、庫存復原
- 觸發器：商品代碼自動生成、系列顏色自動分配

### 2.3 架構優點

- Server-First 架構，Client Component 僅負責 UI 互動
- Design Tokens 系統完整（圓角、陰影、間距、排版全部參數化）
- 支援 4 種主題：Clean Commerce / Neo-Brutalism / Warm Industrial / Soft Depth
- 自動備份 Cron Job（每日 18:00 UTC）
- GitHub Actions CI/CD：type-check → lint → deploy

### 2.4 架構風險

| 風險 | 嚴重度 | 說明 |
|------|--------|------|
| 直連生產資料庫 | 高 | 所有環境共用同一 Supabase 實例，無 staging 環境 |
| Service Role Key 使用範圍 | 中 | `createAdminClient()` 繞過 RLS，需確保僅在 Server Actions 中使用 |
| Cookie 角色快取 | 低 | 5 分鐘內角色變更不會生效，極端情況可能導致權限不一致 |

2. 優惠券驗證（日期、金額、使用次數）
3. 批次查詢商品與等級價格
4. 計算訂單總金額 + 優惠折扣
5. 生成訂單編號（RPC 防競態）
6. 計算運費（RPC 函式）
7. 建立訂單主表
8. 建立訂單明細
9. 建立優惠券/組合優惠快照
10. 建立訂單時間線
11. `revalidatePath()` + 成功導向

### 3.4 發現的問題

#### 嚴重度：高

| # | 問題 | 影響 | 建議 |
|---|------|------|------|
| H1 | 優惠券併發使用無顯式鎖定 | 極端情況下同一優惠券可能被兩筆訂單同時使用 | 在 `UPDATE user_coupons` 時使用 `FOR UPDATE` 行級鎖 |

#### 嚴重度：中

| # | 問題 | 影響 | 建議 |
|---|------|------|------|
| M1 | 組合優惠與普通商品重複 | 同一商品可同時出現在普通項目和組合優惠中，可能導致重複計算 | 在 `createOrder()` 中增加交叉檢查 |
| M2 | 等級變更中途購物 | 客戶購物途中被管理員改等級，結帳使用新等級價格 | 在 `validateCartBeforeCheckout()` 快取初始等級 |
| M3 | 訂單總金額未檢查非負 | 極端折扣組合可能導致負金額（理論上不太可能） | 新增 `finalTotalAmount >= 0` 防禦性檢查 |
| M4 | 結帳重複提交防護 | `isSubmitting` 狀態存在但需確認 UI 按鈕是否同步 disabled | 驗證 submit 按鈕在提交中已禁用 |

#### 嚴重度：低

| # | 問題 | 影響 | 建議 |
|---|------|------|------|
| L1 | 庫存不自動扣除 | 訂單建立後不修改 `products.stock`，需手動管理 | 評估是否為設計決策，若是則應文件化 |
| L2 | 系列最低價格未計算等級價格 | `getSeriesProductsWithPrice()` 只使用零售價 | 對每個用戶等級計算真實最低價 |
| L3 | 優惠券有效期即時檢查 | Zod 驗證了日期範圍格式，但使用時未嚴格檢查當前時間 | 在 SQL 查詢層加 `NOW() BETWEEN valid_from AND valid_until` |
