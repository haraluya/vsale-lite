# 站點二遷移 - 快速總結

## ✨ 解決的問題

您之前遇到的問題：
- ❌ SQL 備份檔案太大（backup.sql > 10MB）
- ❌ 手動分割檔案（part-01.sql, part-02.sql...）
- ❌ 觸發 Prompt 長度限制錯誤
- ❌ 處理複雜且容易出錯

## ✅ 新的解決方案

### 兩個簡單指令搞定

```bash
# 1. 比較差異
pnpm site2:compare

# 2. 執行遷移
pnpm site2:migrate
```

### 工作原理

```
主站點 (API) → [ 批次讀取 100 筆 ] → 站點二 (API)
                     ↓
               即時進度顯示
                     ↓
              自動處理外鍵依賴
```

**無需中間 SQL 檔案！**

## 🚀 使用流程

### 第一次使用

1. **設定環境變數** (只需設定一次)

在 `.env.local` 最後新增：

```env
NEXT_PUBLIC_SUPABASE_URL_SITE2=https://rdyvmgomjdglflrcfijs.supabase.co
SUPABASE_SERVICE_ROLE_KEY_SITE2=eyJhbGci...（從 SITE_CREDENTIALS.md 複製）
```

2. **確認站點二已完成 Migration**

```bash
supabase link --project-ref rdyvmgomjdglflrcfijs
supabase db push
```

### 每次遷移

```bash
# 步驟 1: 檢查差異
pnpm site2:compare

# 步驟 2: 執行遷移
pnpm site2:migrate

# 步驟 3: 驗證結果
pnpm site2:compare  # 應該顯示 ✅ 一致
```

## ⚠️ 重要注意事項

### 資料安全

1. **站點二資料會被清空** - 執行前請確認
2. **不可逆操作** - 無法復原
3. **僅遷移業務資料** - 不包含使用者/訂單

### 遷移清單

#### ✅ 會遷移
- 會員等級
- 商品分類
- 商品系列
- 商品資料
- 等級價格
- 優惠券設定

#### ❌ 不遷移（站點獨立）
- 使用者帳號
- 管理員帳號
- 訂單資料
- 操作日誌

## 🐛 常見錯誤

### 錯誤 1: 環境變數未設定

```
❌ 錯誤: 請在 .env.local 設定站點二的環境變數
```

**解決**: 檢查 `.env.local` 是否包含 `SITE2` 配置

### 錯誤 2: 權限不足

```
permission denied for table xxx
```

**解決**: 確認使用的是 `service_role` key（從 `SITE_CREDENTIALS.md` 複製）

### 錯誤 3: 欄位結構不一致

```
❌ 欄位結構不一致
  僅主站點有: id, name, created_at...
```

**解決**: 站點二需要先執行 Migration
```bash
supabase link --project-ref rdyvmgomjdglflrcfijs
supabase db push
```

## 🔐 遷移後重要步驟：設定 GCS 雲端備份

**⚠️ 重要**: 完成資料遷移後，**強烈建議**為站點二設定 GCS 雲端備份功能。

### 為什麼需要？

Supabase 免費版**沒有自動備份功能**，設定 GCS 備份可提供：
- ✅ 自動化每日備份
- ✅ 異地容災保護
- ✅ 與主站同等級的資料安全

### 快速設定（10 分鐘）

參考 **[站點二 GCS 備份同步指南](SYNC_GCS_TO_SITE2.md)** 完成設定。
